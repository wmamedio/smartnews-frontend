# Story 1.1.2: Google OAuth Authentication Integration

## Story Status: Done ✅

## Parent Story

[Story 1.1: Frontend - Creator Onboarding & Authentication System](./1.1.frontend.story.md)

## Story

**As a** content creator or subscriber,
**I want** to register and log in using my Google account,
**so that** I can access the platform quickly without creating a new password, reducing friction in the authentication process.

## Acceptance Criteria

1. **Google OAuth Registration**
   - User can click "Sign in with Google" button on `/register/creator` page
   - User can click "Sign in with Google" button on `/register/subscriber` page
   - Clicking button initiates Google OAuth flow with correct `user_type` parameter
   - User is redirected to Google for authentication
   - After successful authentication, user is redirected back to the app
   - OAuth callback properly exchanges authorization code for tokens
   - User account is created with `user_type` correctly set (creator or subscriber)
   - User is redirected to appropriate dashboard based on `user_type`
   - New user sees "Welcome, [Name]!" message (first login)

2. **Google OAuth Login**
   - User can click "Sign in with Google" button on `/login/creator` page
   - User can click "Sign in with Google" button on `/login/subscriber` page
   - Existing Google-authenticated users can log in successfully
   - User is redirected to appropriate dashboard after login
   - Returning user sees "Welcome back, [Name]!" message

3. **OAuth Button UI/UX**
   - Google OAuth button follows shadcn/ui design patterns
   - Button displays Google logo and "Sign in with Google" text
   - Button is positioned above email/password form with "or" divider
   - Button has proper loading state during OAuth flow
   - Button is keyboard accessible (tab navigation, enter to activate)
   - Button follows industry-standard OAuth button design

4. **Error Handling**
   - User sees clear error message if Google authentication fails
   - User sees error if OAuth callback receives invalid state parameter
   - User sees error if authorization code exchange fails
   - User can retry authentication after error
   - Errors are logged for debugging purposes
   - User is not left on blank page if error occurs

5. **Security Requirements**
   - OAuth state parameter is properly validated
   - Authorization code is exchanged securely via backend API
   - No sensitive tokens are exposed to browser (httpOnly cookies)
   - CSRF protection is maintained
   - Redirect URIs are validated

6. **Documentation**
   - `authentication.md` updated with Google OAuth flow section
   - `technical-spec.md` updated with OAuth service methods
   - Sequence diagrams added for Google OAuth flows
   - Implementation examples provided for future developers

## Backend Configuration Required

📋 **Detailed Configuration Guide**: See [BACKEND-OAUTH-CONFIG.md](./BACKEND-OAUTH-CONFIG.md) for complete setup instructions for the backend team.

### Google OAuth Redirect URI Setup

**IMPORTANT**: The backend Google OAuth configuration must use the **frontend callback URL** as the redirect URI, not the backend URL.

#### Required Redirect URIs:

- **Development**: `http://localhost:3000/callback/google`
- **Testing**: `https://localhost:3000/callback/google` (if test frontend exists)
- **Production**: `https://localhost:3000/callback/google`

#### Current Issue:

Google OAuth is currently redirecting to the backend URL (`https://localhost:8000/auth/google/callback`) instead of the frontend URL. This causes the browser to display raw JSON instead of the React callback page.

#### Expected OAuth Flow:

1. User clicks "Sign in with Google" → Frontend calls `POST /auth/google/login`
2. Backend returns `{"redirect_url": "https://accounts.google.com/..."}` → Frontend redirects user
3. User authenticates with Google → **Google redirects to frontend** `http://localhost:3000/callback/google?code=...&state=...`
4. Frontend React page extracts code/state → Frontend calls `GET /auth/google/callback?code=...&state=...`
5. Backend validates code/state and returns tokens → Frontend stores tokens and redirects to dashboard

#### Backend Configuration Steps:

1. In Google Cloud Console, set OAuth 2.0 redirect URI to frontend URL (not backend URL)
2. Update backend OAuth initialization to use frontend callback URL
3. Backend `/auth/google/login` and `/auth/google/register` should return OAuth URL that redirects back to frontend
4. Backend `/auth/google/callback` endpoint should remain as-is (AJAX endpoint for frontend to call)

#### Testing Verification:

- ✅ Frontend successfully calls `/auth/google/login` endpoint
- ✅ Backend returns valid Google OAuth URL
- ✅ User authenticates with Google successfully
- ✅ Backend `/auth/google/callback` returns correct user data and tokens when called via AJAX
- ⚠️ **Pending**: Google needs to redirect to frontend URL instead of backend URL

## Dev Notes

### API Endpoints

**Source:** Backend OpenAPI Spec (https://localhost:8000/openapi.json)

#### POST /auth/google/register

- **Description:** Initiate Google OAuth registration flow with user_type selection
- **Request Body:**
  ```json
  {
    "user_type": "creator" | "subscriber",  // REQUIRED
    "affiliate_hash": "string"               // OPTIONAL
  }
  ```
- **Response:** 200 OK with redirect URL to Google OAuth
- **Security:** None specified (public endpoint)

#### POST /auth/google/login

- **Description:** Initiate Google OAuth login flow for existing users
- **Request Body:** None
- **Response:** 200 OK with redirect URL to Google OAuth
- **Security:** None specified (public endpoint)

#### GET /auth/google/callback

- **Description:** Handle Google OAuth callback for both registration and login
- **Query Parameters:**
  - `code` (string, REQUIRED): OAuth authorization code from Google
  - `state` (string, REQUIRED): OAuth state parameter for CSRF protection
- **Response:** 200 OK with user data and JWT tokens
- **Security:** None specified (handled via OAuth state validation)

### Technical Implementation Details

**Source:** [docs/frontend/architecture/technical-spec.md](../frontend/architecture/technical-spec.md#5-service-layer-pattern)

#### API Client Configuration

- **Base URL:** `process.env.NEXT_PUBLIC_API_URL` or `https://localhost:8000/`
- **Timeout:** 10000ms
- **With Credentials:** true (sends cookies)
- **Request Interceptor:** Automatically includes Bearer token
- **Response Interceptor:** Redirects to /login on 401

#### OAuth State Management Pattern

```typescript
// Generate random state for CSRF protection
const state = crypto.randomUUID();

// Store state in sessionStorage
sessionStorage.setItem("oauth_state", state);

// Include state in OAuth request
const response = await apiClient.post("/auth/google/register", {
  user_type: "creator",
  state,
});

// On callback, validate state matches
const callbackState = new URLSearchParams(window.location.search).get("state");
const storedState = sessionStorage.getItem("oauth_state");
if (callbackState !== storedState) {
  throw new Error("Invalid OAuth state");
}
sessionStorage.removeItem("oauth_state"); // Clean up
```

### Security Considerations

**Source:** [docs/frontend/features/authentication.md](../frontend/features/authentication.md#security-best-practices)

#### CSRF Protection

- OAuth state parameter MUST be validated
- State value stored in sessionStorage
- State cleared after validation

#### Token Storage

- Access token: httpOnly cookie (15 min lifetime)
- Refresh token: httpOnly cookie (7 days lifetime)
- NEVER store tokens in localStorage or sessionStorage
- Tokens set via API route (Next.js server-side)

#### Input Validation

- Validate `user_type` parameter is 'creator' or 'subscriber'
- Validate OAuth state is non-empty string
- Validate authorization code exists and is non-empty

#### Rate Limiting

- Backend handles rate limiting for OAuth endpoints
- Frontend should implement exponential backoff for retries
- Maximum 3 retry attempts for failed requests
