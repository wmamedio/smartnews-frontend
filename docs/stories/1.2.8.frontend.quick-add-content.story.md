# Story 1.2.8: Quick Add Content & Smart Import Flow

## Status
Done

## Story

**As a** creator,
**I want** to quickly import individual articles or continuous feeds from any URL directly from the dashboard,
**so that** I can rapidly build my content library without navigating through complex source setup flows.

## Acceptance Criteria

1. Dashboard displays a "Quick Add Content" card (only when user has at least one feed)
2. User can paste any URL and the system auto-detects content type:
   - **Single content** (article, blog post) → imports immediately, auto-approves, shows success
   - **Continuous feed** (RSS, YouTube channel) → opens wizard for keyword configuration
3. For continuous feeds, AI keyword suggestions are fetched and pre-populated in wizard
4. Content Library page has "Add Content" button that opens wizard defaulting to single content mode
5. Sources page shows "Create a Feed First" alert if user has no feeds when trying to add source
6. User must select which feed to associate content/source with (auto-selected if only one feed)
7. All imported content is properly associated with a feed before being saved

## Dev Notes

### API Endpoints Used
- `POST /feed-sources/smart-import` - Auto-classifies URL and creates source + item for single content
- `POST /feed-sources/{id}/pull` - Pulls content from continuous feed source
- `POST /feed-sources/{id}/rescore-all` - Applies keyword scoring to all items
- `GET /feed-sources/validate-url` - Returns AI keyword suggestions
- `PUT /feeds/{id}` - Updates feed with new source IDs

### Smart Import Response Structure
```typescript
interface SmartImportResponse {
  feed_source: FeedSource;
  source_item: { id, title, description, link, status, ... };
  classification: "single_content" | "continuous_feed";
  detected_type: SourceType;
  is_new: boolean;
}
```

### Key Components

**New Hooks:**
- `useSmartImport` - Main hook for URL import logic with callbacks for different content types
- `useCreatorFeeds` - Hook for checking user's feeds, provides `hasFeeds` boolean
- `useContentRating` - Centralized content rating logic with keyword extraction and session tracking

**New Components:**
- `QuickAddCard` - Dashboard card with URL input and feed selector
- `FeedSelector` - Reusable dropdown for selecting user's feeds
- `NoFeedsAlert` - Alert dialog shown when user has no feeds

### Import Flow Diagram
```
User selects feed → pastes URL → useSmartImport
    ├── single_content → auto-approve → add source to feed → toast success → done
    └── continuous_feed → fetch AI keywords → open AddSourceWizard(feedId)
                              → user configures keywords
                              → save → add source to feed → pull → rescore → done
```

### Feed Association Flow
```
1. QuickAddCard shows FeedSelector (only when URL has content)
2. Auto-selects most recent non-draft feed
3. On import:
   - Single content: addSourceToFeed() + set item to "published"
   - Continuous feed: pass feedId to AddSourceWizard → associate after creation
```

### useContentRating Hook
Centralized rating logic used across ContentCardGrid, FeedPreviewStep, and Dashboard:
```typescript
const {
  handleRating,        // Rate content (up/down) with keyword extraction
  handleAddKeywords,   // Add selected keywords to source
  keywordDialogOpen,   // Dialog visibility state
  setKeywordDialogOpen,
  keywordDialogData,   // Keywords, mode, source info for dialog
} = useContentRating({
  feedId,              // For "skip dialog for this feed" feature
  isLibraryContext,    // For library-specific skip preference
  invalidateQueryKeys, // Query keys to invalidate after rating
  onRatingSuccess,     // Callback for custom handling (e.g., update local state)
});
```

Features:
- Updates item status (ready_for_publish or rejected)
- Extracts keywords via rescore if needed (for pending items)
- Filters existing source keywords from suggestions
- Tracks keywords added during session (per source) to avoid re-suggesting
- Manages keyword dialog state

### YouTube Thumbnail Fix
YouTube embeds often fail due to playback restrictions. Solution:
- Detect YouTube URLs and extract video ID
- Display clickable thumbnail instead of iframe
- Link opens YouTube directly in new tab
- Uses `maxresdefault.jpg` with `hqdefault.jpg` fallback
