## Story Status: Done ✅

## Parent Story

[Story 1.2: Frontend - Content Curation & Ingestion Interface](./1.2.frontend.story.md)

## Overview

Comprehensive dev mode testing infrastructure enabling frontend development and UI testing without requiring a functional backend API. Includes sample data generation, user-controlled toggles, and graceful fallback patterns for feeds, feed items, and workflow completion.

---

## Problem Statement

**Challenge**: Frontend development blocked when backend APIs are unavailable or return errors
**Solution**: Smart fallback system with user-controlled sample data toggles
**Result**: Unblocked development + full UI testing + production-ready code

---

## Architecture

### Three-Layer Fallback System

**Layer 1: API Success + Empty Response**

```typescript
const result = await api.fetch();
if (DEV_MODE && useSampleData && result.empty) {
  return mockData; // Show sample data
}
return result; // Show empty state
```

**Layer 2: API Failure**

```typescript
catch (error) {
  if (DEV_MODE && useSampleData) {
    return mockData;  // Graceful fallback
  }
  throw error;  // Show real error
}
```

**Layer 3: Workflow Completion**

```typescript
try {
  await createFeed({...});
} catch (error) {
  if (DEV_MODE) {
    showSuccessState();  // Allow workflow testing
  } else {
    throw error;  // Production shows error
  }
}
```

## Technical Patterns

### 1. State-Driven Query Refetch

**Problem**: How to trigger refetch when toggle changes?

**Solution**: Include toggle state in queryKey

```typescript
const { data } = useQuery({
  queryKey: ["feeds", useSampleData], // ← Key changes
  queryFn: async () => {
    // Query logic respects useSampleData
  },
});
```

**Result**: React Query automatically refetches when `useSampleData` changes

### 2. Conditional Fallback Pattern

**Pattern**:

```typescript
// Three conditions must ALL be true
if (
  shouldUseSampleData() && // Dev mode enabled
  useSampleData && // User toggle ON
  result.empty // API returned empty
) {
  return mockData;
}
```

**Why All Three?**:

- `shouldUseSampleData()`: Environment check (dev only)
- `useSampleData`: User preference (respects toggle)
- `result.empty`: Only fill gaps (not override real data)

### 3. Auto-Enable Pattern

**Pattern**:

```typescript
useEffect(() => {
  if (
    !hasCheckedAutoLoad && // First time only
    !isLoading && // Data loaded
    isDevMode() && // Dev environment
    data.empty && // No real data
    !useSampleData // Not already enabled
  ) {
    setUseSampleData(true); // Auto-enable
    setHasCheckedAutoLoad(true); // Prevent re-trigger
    toast.info("Using sample data...");
  }
}, [isLoading, data]);
```

**Why?**: Smooth first-time experience without requiring manual toggle
