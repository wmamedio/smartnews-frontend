## User Story

**As a** creator,
**I want** to browse my content library with visual cards, easy filtering, and discoverable bulk actions,
**so that** I can quickly find and select content items to organize into feeds.

---

## Story Context

### Background

Story 1.2 successfully delivered functional content curation with a table-based library (QA: 92/100). However, user research identified UX friction points:

1. **Visual Scanning:** Table layout is developer-centric, not creator-friendly
2. **Multi-Select Feedback:** Checkbox selection lacks visual feedback
3. **Bulk Action Discoverability:** Actions hidden in dropdown menus
4. **Feed Creation Prep:** Story 1.3 requires robust multi-select workflow

This story **enhances** the existing library with:

- Visual card-based layout (Pinterest/Unsplash pattern)
- Advanced filtering and search
- Floating bulk action toolbar
- View toggle (grid/list) for user preference

### Integration Points

- **Story 1.2:** Builds on existing `ContentGrid.tsx` and library components
- **Story 1.2.5:** Uses dashboard layout and **nested sidebar navigation** (updated by Story 1.2.7)
- **Story 1.2.7:** Navigation restructured - Library now accessible via `/content/library` with sidebar nav
- **Story 1.3:** **Blocks** - Bulk selection workflow is prerequisite for feed creation
- **Backend API:** `/feed-items/` endpoints remain unchanged (filter params exist)

### Key Constraints

1. **No Breaking Changes:** Existing `ContentGrid.tsx` remains available as fallback
2. **Backend-Optional:** Thumbnail support is P2, use placeholders initially
3. **Performance:** Must maintain <1s load time for 20 items
4. **Accessibility:** WCAG 2.1 AA compliance required

## Acceptance Criteria

### 1. Visual Card Library (Core)

**AC 1.1: Card Grid Layout**

- Content library displays as responsive card grid (not table by default)
- Grid adapts to screen size: 1 column (mobile), 2 columns (tablet), 3-4 columns (desktop)
- Cards have consistent aspect ratio (16:9 thumbnail area)
- Grid gap is 16px (gap-4) with proper spacing

**AC 1.2: Content Card Design**

- Each card displays:
  - Thumbnail image area (aspect-video, bg-muted)
  - Fallback placeholder icon when no thumbnail (FileText icon)
  - Title (text-sm, line-clamp-2)
  - Description (text-xs, line-clamp-2, text-muted-foreground)
  - Status badge (top-right corner)
  - Published date (footer, with Calendar icon)
  - Actions dropdown (visible on hover, MoreVertical icon)
- Card has hover state (scale-105 for thumbnail)
- Card uses shadcn/ui Card component structure

**AC 1.3: Multi-Select with Visual Feedback**

- Checkbox in top-left corner of each card
- Selected cards show ring highlight (`ring-2 ring-primary ring-offset-2`)
- Checkbox has backdrop-blur background for visibility over thumbnails
- Selection state persists across pagination
- Click anywhere on card to select (not just checkbox)

### 2. Enhanced Filtering & Search

**AC 2.1: Search Bar**

- Search input with magnifying glass icon (left-aligned)
- Placeholder text: "Search content by title or description..."
- Debounced search (300ms delay)
- Search triggers API query with `search` parameter
- Search input sanitized before API call (trim whitespace, basic XSS prevention via React auto-escaping)

**AC 2.2: Filter Controls**

- Status filter dropdown: All / Pending / Published / Archived
- Source type filter dropdown: All Sources / RSS Feeds / Manual URLs / Social Media
- Date range filter dropdown: Today / This Week / This Month / All Time
- Filters apply to API query parameters

**AC 2.3: Active Filters Display**

- Active filters shown as dismissible badges below filter bar
- Badge shows filter type and value (e.g., "Status: published")
- X icon on each badge to remove individual filter
- "Clear all" button to reset all filters at once
- Active filter count visible when filters applied

### 3. View Toggle

**AC 3.1: Grid/List Toggle**

- ToggleGroup component with two options:
  - Grid view (LayoutGrid icon)
  - List view (List icon)
- Default view: Grid
- Toggle state persists in localStorage
- List view shows existing `ContentGrid.tsx` table
- Grid view shows new `ContentCardGrid.tsx`

### 4. Bulk Actions Toolbar

**AC 4.1: Floating Action Bar**

- Appears at bottom-center when 1+ items selected
- Fixed positioning with z-50 (always visible, doesn't scroll)
- Slide-up animation on appearance (`animate-in slide-in-from-bottom`)
- Shadow-lg and border-2 for prominence

**AC 4.2: Bulk Action Buttons**

- Selection count display with "select all" checkbox
- Actions available:
  - Publish (CheckCircle icon)
  - Archive (Archive icon)
  - **Create Feed** (Plus icon, primary button) - placeholder for Story 1.3
  - Delete (Trash2 icon, destructive color)
- Clear selection button (X icon)
- Actions grouped with vertical separators

**AC 4.3: Bulk Action Functionality**

- Publish: Calls `/feed-items/bulk-action` with action="publish"
- Archive: Calls `/feed-items/bulk-action` with action="archive"
- Delete: Shows confirmation dialog, then calls bulk delete endpoint
- Create Feed: Disabled with tooltip "Coming in Story 1.3"
- Actions update React Query cache optimistically

### 5. Responsive & Accessibility

**AC 5.1: Responsive Design**

- Mobile (<640px): 1 column grid, filters in bottom sheet
- Tablet (640-1023px): 2 column grid
- Desktop (1024px+): 3-4 column grid
- Touch targets minimum 44x44px (WCAG AA)

**AC 5.2: Keyboard Navigation**

- Tab key navigates through cards
- Space key toggles card selection when focused
- Enter key opens actions dropdown
- Escape key clears selection

**AC 5.3: Screen Reader Support**

- Checkbox has aria-label: "Select {item.title}"
- Bulk action bar has role="toolbar" with aria-label
- Filter badges have descriptive aria-labels
- Focus states visible on all interactive elements

### 6. Performance & Quality

**AC 6.1: Performance Metrics**

- Initial load time: <1 second for 20 cards
- Filter response time: <300ms
- Smooth scrolling at 60fps
- Lazy load images below the fold

**AC 6.2: Code Quality**

- Zero hardcoded colors (use CSS variables only)
- All components use shadcn/ui primitives
- TypeScript strict mode with no `any` types
- Proper error handling and loading states

**AC 6.3: Testing Coverage**

- Unit tests for ContentCard, BulkActionBar components
- Integration tests for filter + selection workflows
- E2E test: Select multiple cards → bulk publish → verify state
- Accessibility audit passes (axe-core)

### Key Implementation Details

#### 1. Component Architecture

**ContentCardGrid.tsx** (Main Component)

- Fetches data with `useQuery` (same as ContentGrid)
- Maps items to `ContentCard` components
- Manages pagination state
- Integrates with `useContentSelection` store

**ContentCard.tsx** (Presentational)

- Receives `item`, `isSelected`, `onSelect` props
- Pure component (no data fetching)
- Uses shadcn/ui Card, Badge, DropdownMenu

**ContentFilters.tsx** (Filter Bar)

- Manages filter state locally
- Debounces search input (300ms)
- Emits filter changes to parent via callback
- Displays active filters as badges

**BulkActionBar.tsx** (Floating Toolbar)

- Conditionally rendered when `selectedCount > 0`
- Fixed positioning with high z-index
- Calls bulk action mutations from `feedItemsService`
- Shows toast notifications

#### 2. State Management

**Selection State (Zustand)**

```typescript
interface ContentSelectionStore {
  selectedIds: Set<number>;
  toggleSelection: (id: number) => void;
  selectAll: (ids: number[]) => void;
  clearSelection: () => void;
  isSelected: (id: number) => boolean;
}
```

**Filter State (URL Query Params)**


## Risks & Mitigation

### Risk 1: Performance with Card Layout

**Risk Level:** LOW

**Scenario:** Card layout slower than table with many items

**Mitigation:**

- Pagination remains (20/50/100 per page)
- Lazy load images below fold
- Virtual scrolling if needed (>100 items per page)
- Performance testing in AC 6.1

### Risk 2: User Preference for Table View

**Risk Level:** LOW

**Scenario:** Some creators prefer table view

**Mitigation:**

- View toggle allows switching to list view (table)
- User preference persists in localStorage
- Both views maintained side-by-side

### Risk 3: Bulk Action Discoverability

**Risk Level:** MEDIUM

**Scenario:** Creators don't notice floating action bar

**Mitigation:**

- Prominent slide-up animation draws attention
- Bottom-center positioning (hard to miss)
- Tutorial tooltip on first selection (future enhancement)
- User testing during beta rollout
