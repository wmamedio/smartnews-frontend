# Story 1.3.2: Frontend - Move Keyword Filters & Delivery Frequency to Source Level

## Story Status: ✅ Done

## Parent Story

**Story 1.3**: Frontend - Feed Creation & Publication System

## User Story

As an approved creator,
I want to configure keyword filters (good/bad keywords) AND delivery frequency when creating or editing feed sources,
So that each source can have its own AI-powered filtering rules and sync schedule that match the backend API design.

## Story Context

### Background

During Story 1.3 implementation, keyword filtering (include/exclude keywords) was placed at the feed level in the Feed Creation wizard (Step 3: FilterConfigurationStep). Additionally, there is no UI for configuring `sync_schedule` (how often to check sources for new content).

However, the backend API design shows that `good_keywords`, `bad_keywords`, `min_relevance_score`, and `sync_schedule` are **feed source-level attributes** configured via POST/PUT `/feed-sources/` endpoints - NOT feed-level attributes.

**Important**: The PublishSettingsStep (Step 4 in wizard) already handles newsletter delivery frequency for SUBSCRIBERS (how often they receive emails). This is different from sync_schedule, which controls how often CREATORS check sources for new content.

This story corrects the architectural misalignment by:

1. Moving keyword configuration from wizard to source dialogs
2. Adding sync_schedule configuration to source dialogs (new feature)
3. Removing the FilterConfigurationStep from the feed creation wizard

### What This Story Changes

**CRITICAL DISTINCTION**:

- **Source Sync Schedule**: How often CREATORS check sources for new content (THIS STORY - adding to source dialogs)
- **Newsletter Delivery Frequency**: How often SUBSCRIBERS receive emails (EXISTING - stays in PublishSettingsStep)

**From Story 1.3 (Current Implementation)**:

- Keywords (good/bad) managed in feed creation wizard Step 3 (FilterConfigurationStep)
- No sync_schedule configuration anywhere (missing feature)
- Keywords stored in feed builder store
- No backend integration (keywords never sent to API)

**To Story 1.3.2 (Correct Implementation)**:

- Keywords managed in CreateSourceDialog and EditSourceDialog
- Sync schedule (sync_schedule) added to CreateSourceDialog and EditSourceDialog
- Sent to backend via POST/PUT `/feed-sources/` API
- Each source has its own filtering configuration AND sync schedule
- FilterConfigurationStep component REMOVED from wizard (Step 3 deleted)
- Wizard reduced from 5 steps to 4 steps

**NOT CHANGED** (Important - these stay in PublishSettingsStep):

- Newsletter delivery frequency (daily/weekly/biweekly/monthly) - this is for SUBSCRIBERS
- Send time and days of week configuration
- Auto-send and publish settings

```typescript
// POST /feed-sources/ and PUT /feed-sources/{id}
interface CreateFeedSourceRequest {
  name: string;

  configuration: object;
  good_keywords?: string[]; // ✅ Source-level attribute

}

// POST /subscriptions/ and PUT /subscriptions/{id} - For later implementation
interface SubscriptionRequest {
  newsletter_frequency?: number; // ✅ Subscription-level (same units as sync_schedule)
}
```

## Technical Notes

### IMPORTANT: Sync Schedule vs Newsletter Frequency

**Two Different Concepts**:

1. **`sync_schedule` (Source-level - THIS STORY)**:
   - Configured by CREATOR when adding/editing a source
   - Controls how often the system checks the source for new content
   - Values in minutes: 0 (immediate), 1440 (daily), 10080 (weekly), 43200 (monthly)
   - Sent via POST/PUT `/feed-sources/` endpoint
   - This is what we're implementing in Story 1.3.2

2. **`newsletter_frequency` (Subscription-level - FUTURE STORY)**:
   - Configured by SUBSCRIBER when subscribing to a feed
   - Controls how often the subscriber receives newsletter emails
   - Same units (minutes) but different purpose
   - Sent via POST/PUT `/subscriptions/` endpoint
   - NOT part of this story - for future implementation

**UI Labels**:

- CreateSourceDialog: "Sync Frequency" (for sync_schedule)
- Future SubscribeDialog: "Newsletter Frequency" (for newsletter_frequency)

### Keyword State Management Pattern

**CreateSourceDialog**:

```typescript
const [goodKeywords, setGoodKeywords] = useState<string[]>([]);
const [badKeywords, setBadKeywords] = useState<string[]>([]);

// Add keyword helper
const addGoodKeyword = (keyword: string) => {
  const trimmed = keyword.trim();
  if (trimmed && !goodKeywords.includes(trimmed)) {
    setGoodKeywords([...goodKeywords, trimmed]);
    setKeywordInput(""); // Clear input
  }
};

// Remove keyword helper
const removeGoodKeyword = (keyword: string) => {
  setGoodKeywords(goodKeywords.filter((k) => k !== keyword));
};
```

### API Integration Pattern

**Create Source with Keywords & Sync Schedule**:

```typescript
await feedSourcesService.create({
  name: name.trim(),
  source_type: sourceType,
  configuration: { url: url.trim() },
  good_keywords: goodKeywords.length > 0 ? goodKeywords : undefined,
  bad_keywords: badKeywords.length > 0 ? badKeywords : undefined,
  min_relevance_score: minRelevanceScore !== 50 ? minRelevanceScore : undefined,
  sync_schedule: syncSchedule !== 1440 ? syncSchedule : undefined, // Default daily
});
```

**Update Source with Keywords & Sync Schedule**:

```typescript
await feedSourcesService.update(source.id, {
  name: editedName,
  configuration: { url: editedUrl },
  good_keywords: editedGoodKeywords,
  bad_keywords: editedBadKeywords,
  min_relevance_score: editedScore,
  sync_schedule: editedSyncSchedule,
});
```
