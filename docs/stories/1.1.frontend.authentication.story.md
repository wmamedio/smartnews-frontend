# Story 1.1: Frontend - Creator Onboarding & Authentication System

## Story Status: Done ✅

## User Story

As a content creator,
I want to quickly register for SmartNews through an intuitive web interface and complete my profile setup,
So that I can start using the platform immediately without being forced to connect social accounts, with the option to connect them later to unlock revenue estimation features.

**CRITICAL FLOW CHANGE (2025-09-30):**
Registration flow changed to eliminate onboarding friction. Creators now go directly to dashboard after registration. Profile completion and social authentication are optional features accessible from dashboard/settings.

## Story Context

### Integration Points

- **Backend API**: FastAPI endpoints at `https://localhost:8000/`
- **Authentication**: OAuth2 with JWT tokens via `/auth/register`, `/auth/login`, `/auth/me`
- **OAuth Providers**: Social authentication via `/social/{provider}/redirect` and `/social/{provider}/callback`
- **Revenue API**: Estimation service at `/creator/revenue/estimate` and `/creator/revenue/projections`
- **Profile API**: Creator profile management at `/creator/profile` with file upload support at `/creator/profile/upload`
- **Application**: Creator application submission at `/creator/apply`

### Technology Stack

- **Framework**: Next.js 15.1 with App Router
- **UI Components**: shadcn/ui (login-02 block for auth forms)
- **State Management**: Zustand for auth state, React Query for server state
- **Forms**: React Hook Form + Zod validation
- **HTTP Client**: Axios with interceptors for Bearer token management
- **Styling**: Tailwind CSS with custom theme
- **File Upload**: Support for multipart/form-data for profile images

## Acceptance Criteria

### Functional Requirements

1. **Registration Flow** _(Updated 2025-10-08)_
   - **Separate pages for creators and subscribers** with dedicated branding
   - Single-page registration form matching login-02 pattern
   - Email/password form with real-time validation
   - **Role pre-determined by URL** (`/register/creator` or `/register/subscriber`)
   - Cross-linking to switch between creator/subscriber registration
   - Email verification with resend capability
   - Loading states and error handling
   - Smart redirect: `/register` → `/register/creator` (default)

2. **Social Authentication (Optional - Post Registration)**
   - Social authentication is NOT part of the core registration flow
   - Users can connect accounts later via settings/profile page
   - OAuth connection available for YouTube, Twitter, Reddit
   - Graceful handling when no social accounts connected

3. **Revenue Estimation Display (Conditional)**
   - Show only when social accounts are connected
   - If no accounts connected: Display prompt "Connect your social networks to estimate your revenue"
   - When connected: Interactive revenue calculator component
   - Animated number counting for dramatic effect
   - Breakdown by connected platforms only
   - "What if" sliders for growth projections

4. **Profile Setup Interface**
   - Avatar upload with preview and crop functionality
   - Rich text bio editor with character limit
   - Social links input with validation
   - Category/niche selection with autocomplete

5. **Application Submission**
   - Review screen showing all entered information
   - Terms of service acceptance with scrollable modal
   - Submit button with loading state
   - Success confirmation with next steps
   - Application status tracking component

### UI/UX Requirements

6. **Responsive Design**
   - Mobile-first approach with touch-optimized inputs
   - Desktop layout with side illustration/testimonials
   - Tablet-friendly intermediate layouts
   - Consistent spacing using design system scale

7. **Visual Feedback**
   - Skeleton loaders during data fetching
   - Toast notifications for success/error messages
   - Form field validation with inline errors
   - Progress saving with localStorage backup

8. **Accessibility**

### Technical Requirements

9. **Authentication State Management**

   ```typescript
   // Zustand store structure
   interface AuthStore {
     user: User | null;
     tokens: { access: string; refresh: string } | null;
     isAuthenticated: boolean;
     login: (credentials: LoginDTO) => Promise<void>;
     logout: () => void;
     refreshToken: () => Promise<void>;
   }
   ```

10. **API Integration**
    - Axios interceptors for Bearer token authentication
    - OAuth2 token management with access/refresh tokens
    - Error transformation for FastAPI validation errors
    - Request cancellation for component unmount
    - Response caching for revenue estimates
    - Handle FastAPI's HTTPValidationError responses

11. **Form Validation Schemas**
    ```typescript
    // Zod schemas for each form
    const registrationSchema = z
      .object({
        email: z.string().email(),
        password: z.string().min(8).regex(/[A-Z]/).regex(/[0-9]/),
        confirmPassword: z.string(),
        role: z.enum(["creator", "subscriber"]),
      })
      .refine((data) => data.password === data.confirmPassword);
    ```

### Security Review

**CONCERNS identified:**

1. API proxy allows wildcards in CORS headers (Access-Control-Allow-Origin: \*) - should restrict to specific domains in production
2. No rate limiting visible on authentication endpoints - vulnerable to brute force attacks
3. Tokens stored in cookies without httpOnly flag (client-side cookies via js-cookie)
4. No CSRF protection mechanism implemented

**Recommendations:**

- Implement rate limiting on /auth/login and /auth/register endpoints
- Use httpOnly cookies set by backend instead of client-side cookie management
- Restrict CORS origins to specific allowed domains
- Add CSRF token validation for state-changing operations

