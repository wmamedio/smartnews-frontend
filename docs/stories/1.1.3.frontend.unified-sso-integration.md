## Dev Notes

### Background & Context

**From Backend Story 1.1.1 (Unified SSO Authentication Endpoint):**

- Backend implemented new unified SSO endpoints: `POST /auth/sso/authenticate` and `GET /auth/sso/callback`
- Unified endpoint automatically decides whether to register or login based on email lookup
- Response includes `is_new_user` flag to indicate if registration occurred
- Backend remains backward compatible with old three-endpoint pattern
- Implementation tested and verified (15 new tests, all passing, 69 total tests passing)

**Current Frontend Implementation (Story 1.1.2):**

- Uses three separate endpoints: `/auth/google/register`, `/auth/google/login`, `/auth/google/callback`
- Frontend makes the register vs. login decision upfront
- Implementation is production-ready (43 tests passing, QA approved)
- No urgent need to change; this is a refinement opportunity

**Why Unify?**

1. **Simplicity**: Single OAuth flow instead of two parallel flows
2. **Maintainability**: Less code duplication and branching
3. **Alignment**: Frontend and backend architecture are cohesive
4. **Future-proof**: Cleaner foundation for adding more OAuth providers

### Backend API Specification

**Verification:** This specification is based on Backend Story 1.1.1 (Unified SSO Authentication Endpoint)
created on 2025-10-14 with 15 new tests (69 total passing).

**Unified Endpoint: POST /auth/sso/authenticate**

- **Location:** Backend Story 1.1.1, Dev Notes section
- **Purpose:** Initiate unified Google OAuth flow
- **Query Parameters:**
  - `user_type` (optional): 'creator' or 'subscriber', defaults to 'subscriber'
  - `affiliate_hash` (optional): Affiliate tracking hash
- **Response:** `{'redirect_url': 'https://accounts.google.com/...?state=xyz&...}'}`
- **Usage:** Call this to start OAuth flow, get redirect URL, send user to Google

**Unified Endpoint: GET /auth/sso/callback**

- **Location:** Backend Story 1.1.1, Dev Notes section
- **Purpose:** Handle Google OAuth callback (unified register-or-login)
- **Query Parameters:**
  - `code` (required): Authorization code from Google
  - `state` (required): State token (includes encoded user_type and affiliate_hash)
- **Response (New User - Registration):**
  ```json
  {
    "message": "Creator account created successfully via Google SSO",
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "bearer",
    "user": {
      "id": "uuid",
      "email": "user@example.com",
      "first_name": "John",
      "last_name": "Doe",
      "user_type": "creator",
      "is_active": true,
      "profile": {...}
    },
    "is_new_user": true
  }
  ```
- **Response (Existing User - Login):**
  ```json
  {
    "message": "Successfully authenticated via Google SSO",
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "token_type": "bearer",
    "user": {
      "id": "uuid",
      "email": "user@example.com",
      "first_name": "John",
      "last_name": "Doe",
      "user_type": "creator",
      "is_active": true,
      "profile": {...}
    },
    "is_new_user": false
  }
  ```
- **Key Difference:** `is_new_user` flag indicates if account was just created (registration) or already existed (login)

### Frontend Implementation Pattern

**Key Points:**

1. **State Extraction:** Backend returns state as part of `redirect_url`, frontend must extract and store it (same as current pattern)
2. **Callback Handling:** Frontend callback page receives code and state, calls `GET /auth/sso/callback?code=...&state=...`
3. **New User Detection:** Use `is_new_user` flag to determine welcome message
4. **Redirect Logic:** Auto-redirect based on `user_type` and `is_new_user` status (already implemented in current story)

#### Phase 2: Core Implementation (Task 2)

**File:** `src/lib/stores/auth-store.ts`

**Add New Method - googleSSO():**

```typescript
async googleSSO(userType?: string): Promise<{ redirect_url: string }> {
  const params = new URLSearchParams();
  if (userType) params.append('user_type', userType);

  const affiliate_hash = new URLSearchParams(window.location.search).get('affiliate_hash');
  if (affiliate_hash) params.append('affiliate_hash', affiliate_hash);

  const response = await api.post(`/auth/sso/authenticate?${params}`);
  return response.data;
}
```

**Add New Method - handleGoogleCallback():**

```typescript
async handleGoogleCallback(code: string, state: string) {
  const response = await api.get(`/auth/sso/callback?code=${code}&state=${state}`);
  // Response includes: access_token, user, is_new_user flag
  return response.data;
}
```

**Optional - Backward Compatibility:**

```typescript
async googleRegister(userType?: string) {
  return this.googleSSO(userType); // Delegate to unified method
}

async googleLogin() {
  return this.googleSSO(); // Delegate to unified method
}
```

**Security Notes:**

- State parameter extracted from redirect_url (backend provides it)
- Token storage in httpOnly cookies (backend handles)
- No token exposure to frontend JavaScript
