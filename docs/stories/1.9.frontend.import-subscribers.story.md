# Story 1.9: Import Subscribers - Brownfield Addition

## User Story

As a **creator**,
I want to **bulk import subscribers from CSV files or paste multiple emails**,
So that **I can quickly add my existing audience to my smartfeed subscriber list**.

## Story Context

**Existing System Integration:**

- Integrates with: Subscriber management system (to be verified with backend API)
- Technology: Next.js 14, TypeScript, shadcn/ui components
- Follows pattern: Similar to the removed content import feature (file upload + bulk URL input)
- Touch points: Subscriber database, authentication system, settings/profile area

## Acceptance Criteria

**Functional Requirements:**

1. **CSV File Upload**
   - Accept CSV files with subscriber data (email, name fields)
   - Validate file format and content before processing
   - Display preview of subscribers to be imported
   - Show validation errors for invalid email addresses

2. **Bulk Email Input**
   - Provide textarea for pasting multiple email addresses
   - Support comma-separated, line-separated, or space-separated emails
   - Validate all email addresses before import
   - Show count of valid vs invalid emails

3. **Import Processing**
   - Process import with progress indicator
   - Show success/failure count after completion
   - Handle duplicate email addresses gracefully
   - Prevent importing emails that already exist in subscriber list

**Integration Requirements:**

4. Existing subscriber management functionality continues to work unchanged
5. New functionality follows existing import/upload pattern (similar to removed content import)
6. Integration with subscriber API maintains current behavior

**Quality Requirements:**

7. Change is covered by appropriate tests
8. Component follows shadcn/ui patterns and uses existing color variables from globals.css
9. No regression in existing subscriber functionality verified
10. Responsive design across all breakpoints (sm → 2xl)
11. Accessibility features included (keyboard nav, ARIA labels, WCAG AA)

## Technical Notes

- **Integration Approach:**
  - Create new page at `/settings/subscribers/import` or `/revenue/import-subscribers`
  - Reuse FileDropzone component pattern from removed import page
  - Use similar bulk input textarea pattern
  - API endpoint: POST `/api/subscribers/import` (to be confirmed with backend)

- **Existing Pattern Reference:**
  - Reference: `src/app/(creator)/content/import/page.tsx` (now removed, but pattern can be followed)
  - Components: FileDropzone, BulkUrlInput patterns

- **Key Constraints:**
  - Must validate email format before sending to backend
  - Must handle large CSV files (pagination or chunking)
  - Must provide clear error messages for failed imports
  - Must follow existing authentication/authorization patterns

## Risk and Compatibility Check

**Minimal Risk Assessment:**

- **Primary Risk:**
  - Importing duplicate or invalid email addresses could cause data integrity issues
  - Large CSV files could cause performance problems or timeout

- **Mitigation:**
  - Implement robust validation before sending to backend
  - Show preview before confirming import
  - Implement chunking for large files
  - Add confirmation dialog for imports > 100 subscribers

- **Rollback:**
  - If import fails, no data is committed
  - Backend should support transaction rollback
  - Frontend can simply hide/remove the import page if issues arise

**Compatibility Verification:**

- [ ] No breaking changes to existing subscriber APIs
- [ ] Database changes (if any) are additive only (backend responsibility)
- [ ] UI changes follow existing design patterns (shadcn/ui + globals.css)
- [ ] Performance impact is negligible (chunking for large imports)
